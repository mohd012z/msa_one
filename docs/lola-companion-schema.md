# Lola Companion interoperability contract

This repository treats **MSA One** as the user's local **msapatcher** Android project and **Lola** as a separate desktop companion repository: <https://github.com/mohd012z/lola>.

MSA One does **not** run Python, PowerShell, Semgrep, apktool, Frida, or arbitrary APK patching inside the Capacitor WebView or Android APK. The contract below is intentionally limited to:

1. exporting a portable handoff manifest from MSA One; and
2. importing a Lola JSON result/evidence report back into MSA One for local viewing.

## Manifest

- schema: `msa.lola.manifest.v1`
- `manifestVersion`: `1`
- generated by: `MSA One Lola Companion`
- transfer model: manual export/import only

### Supported job types

1. `source-security-scan`
   - `semgrepRules` — request Lola Semgrep/security findings
   - `dependencyInventory` — include dependency inventory notes
   - `changedFilesOnly` — operator note that scope may be narrowed manually
2. `apk-inspection`
   - `manifestSummary` — summarize AndroidManifest/package metadata
   - `permissionReview` — review permissions/components/exported surface
   - `signingOverview` — include signing/signature metadata when available

```json
  },
  "job": {
    "id": "lola_job_...",
    "type": "apk-inspection",
    "profile": "apk-inspection",
    "options": {
      "manifestSummary": true,
      "permissionReview": true,
      "signingOverview": false
    }
  },
  "context": {
    "project": {
      "id": "p_...",
      "title": "Client Audit",

    },

      "kind": "apk",

  ]

```

Only user-selected labels and references belong in the manifest. Do **not** place secrets, credentials, or raw project contents into the manifest.

## Result / evidence report

- schema: `msa.lola.result.v1`
- `resultVersion`: `1`
- imported file type: JSON only
- MSA One enforces bounded input sizes plus limits on findings/evidence counts before local storage

MSA One renders imported report content as plain safe text. It does not trust the report as executable HTML.

## Provenance fields

Both sides should preserve:

- manifest/result schema + version
- job/profile id
- generated timestamp
- Lola repository/tool identity
- desktop host/path notes when the operator chooses to include them
- linked MSA project id/title when intentionally associated

## Trust model and explicit limitations

- MSA One is local-first. It does not upload local files or call remote Lola endpoints.
- The Android app only prepares manifests and views imported evidence.
- Lola desktop execution remains outside the mobile sandbox.
- Imported results are untrusted input and must be validated before storage and escaped on render.
- Users must only analyze applications or source code they own or are explicitly authorized to assess.

## Adapter-ready Lola mapping

This PR does not modify `mohd012z/lola`, but the contract is designed so a small Lola-side adapter can map the manifest onto existing desktop entry points already present in that repository:

- source scan path -> `scan-security.ps1`
- APK path -> `scan-apk.ps1` and/or `analyze-apk.py`

Example adapter invocation to add on the Lola side:

```powershell
python lola_manifest_adapter.py `
  --manifest .\msa-one-lola-manifest.json `
  --result .\lola-result.json
```

The adapter should read `job.type`, invoke the appropriate existing Lola desktop workflow, then emit `msa.lola.result.v1`.
